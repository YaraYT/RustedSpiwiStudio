# Rusted Шпижион Студия 0.1.0

Программа созданная для быстрого нахождения фотографий для вдохновления и последующего копирования их в фоторедактор для в заимствование...

Внимание!
Программа целиком и полностью сделана при использовании и полном доверии искусственного интеллекта. Все, что вы читаете, включая сейчас создано с использованием искусственного интеллекта. Если вы против искусственного интеллекта немедленно закройте проект, пока не стало слишком поздно.
Хотя и вправду искусственный интеллект самостоятельно кот, я пытаюсь заниматься так называемым, чекингом, что он тут написал... Хотя и чаще всего это все чистый мрак, который работает на святой силе...
Ниже агент обычно любит приложить, увлекательную документацию о том, что ж этот проект прямо сейчас умеет, или не умеет, если он забудет, или не захочет, то тут будет примерно ничего.

## 0.1.0: что изменилось

- История релизов теперь загружается напрямую из GitHub Releases.
- Добавлена ручная проверка обновлений.
- Добавлено безрамочное окно предложения обновления.
- Обновление проверяет SHA-256 скачанного EXE и не удаляет пользовательские данные.
- Нижняя панель сканирования больше не занимает место, когда программа простаивает.
- Основные элементы интерфейса выровнены по общей геометрии.
- `favicon.ico` используется как основная иконка приложения.

## Памятка по GitHub Release notes

Release notes предназначены прежде всего для обычного пользователя. Пишите коротко и понятно: что добавилось, что исправилось и что стало удобнее. Не помещайте в пользовательскую часть логи сборки, номера коммитов, трассировки исключений, названия внутренних классов и другие технические записи.

Рекомендуемый формат:

```markdown
## Для пользователя
- Добавлена новая возможность.
- Исправлена заметная ошибка.
- Улучшено удобство работы.

## Технические детали
- Здесь можно хранить информацию для разработчиков, если она действительно нужна.
```

В интерфейсе «Что нового» показывается только пользовательская часть до секции `## Технические детали`.

## GitHub Releases для обновлений

Репозиторий релизов: `https://github.com/YaraYT/RustedSpiwiStudio`

Для автоматического обновления релиз должен содержать один опубликованный `.exe`-asset. GitHub REST API предоставляет для release asset поле `digest` вида `sha256:<64 hex>`, и студия сравнивает его с SHA-256 скачанного файла перед заменой текущего EXE.

Обновление заменяет только `RustedShpizhionStudio.exe`. Файлы `config.json`, `config.json.bak`, `index.db`, SQLite `-wal`/`-shm`, `rwmod-cache`, `app.log` и прочие portable-данные намеренно не затрагиваются.

## SQLite и совместимость

Старый рабочий `index.db` намеренно не мигрируется. Формат индекса C# версии остаётся 6, а версия парсера увеличена до 7. Это заставляет 0.1.6-alpha пересобрать устаревший индекс после смены правил классификации ресурсов.

`resources/rusted_warfare_docs.db` переносится как отдельный справочник и не уничтожается при сбросе рабочего индекса.

## Windows-only и Portable

Проект намеренно поддерживает только Windows x64. Кроссплатформенная совместимость не является целью релиза: можно не тянуть лишние абстракции и ориентироваться на Windows и её производительность.

Приложение строго portable. `config.json`, `config.json.bak`, `index.db`, SQLite WAL/SHM-файлы, `rwmod-cache` и `app.log` хранятся рядом с исполняемым файлом, внутри корневой папки приложения. Проект не использует `%AppData%` или `%LocalAppData%` для своих рабочих данных. Папку приложения можно целиком переносить вместе с индексом и настройками.

Portable-режим требует, чтобы каталог приложения был доступен для записи. Размещение EXE в защищённых системных каталогах Windows не поддерживается.

## Сборка в Windows

Требуется .NET 10 SDK и обычная среда Native AOT для Windows.

```powershell
dotnet restore
dotnet build -c Release
dotnet publish -c Release
```

Проект уже настроен на:

- `net10.0-windows`
- `win-x64`
- `PublishAot=true`
- `SelfContained=true`
- `PublishSingleFile=true`
- `PublishTrimmed=true`
- compiled XAML/bindings

`resources/rusted_warfare_docs.db` автоматически копируется в publish-папку.

## 0.1.2-alpha: исправления миграции

- Исправлен критический запуск Avalonia после миграции на C#: AXAML-файлы явно проходят через `AvaloniaXaml`, чтобы precompiled XAML не терялся при сборке и публикации.
- `App.axaml` и окна сохраняют корректный `x:Class`, а code-behind связан с AXAML через MSBuild metadata.
- `Avalonia.Controls.ItemsRepeater` оставлен на доступной версии 12.0.0, без принудительного притягивания несуществующей 12.1.3.
- Убрано хранение конфигурации во внешнем `LocalAppData`.
- `config.json` сохраняется через временный файл с резервной копией `config.json.bak`, поэтому падение во время записи не должно уничтожить рабочий конфиг.
- Версия приложения и changelog повышены до `0.1.2-alpha`.

Сборка и публикация выполняются в Windows через .NET 10 SDK. В текущей среде `dotnet` SDK отсутствует, поэтому готовый Windows `.exe` здесь не собирался.

## 0.2.2-alpha: геометрия, видимость и реальная ленивость

0.2.2-alpha доводит галерею до более предсказуемого состояния: выбранный режим количества карточек теперь реально определяет число колонок, ширина карточки рассчитывается от доступного пространства, миниатюры запрашиваются только для видимой области с небольшим запасом, а нижняя панель сканирования больше не съедает рабочую высоту в обычном режиме.

## 0.2.1-alpha: выравнивание и компактность интерфейса

0.2.1-alpha исправляет визуальные проблемы, заметные после 0.2.0-alpha: сетка карточек и верхняя панель приведены к единому ритму, боковые панели больше не обязаны постоянно занимать рабочее пространство, а состояние карточки больше не зависит от анимационного fade.

- Карточки галереи используют стабильную минимальную ширину и одинаковую геометрию строки.
- Верхняя панель и панель управления галереей согласованы по высоте контролов и отступам.
- Левая панель фильтров теперь сворачивается одной кнопкой и освобождает рабочую площадь галереи.
- Список «Ссылки / ресурсы» справа можно сворачивать и разворачивать отдельно от предпросмотра.
- Карточка больше не исчезает целиком из-за `CardOpacity`; анимация применяется только к визуальному контейнеру.
- Повторная очередь загрузки пропущенных миниатюр при прокрутке сохранена.
